# Openflow Run Storage Layout

## Run Layout

```
~/.openflow/runs/<run-id>/
  metadata.json                # run-level metadata
  events.jsonl                 # unified event timeline (SDK primitives)
  agents/
    <agent-name>/
      events.jsonl             # raw agent runner output (opencode JSON stream)
      messages.jsonl           # prompt / feedback / output timeline
      shell_suggestions/       # agent-suggested shell command replacements
        test.sh                # pending suggestion
        test_20260606_143025.sh # archived after read
```

## Run ID

Format: `YYYYMMDD-<8-hex-chars>`, e.g. `20260606-abbfdab9`.

Generated by the Go runner, passed to the SDK via `OPENFLOW_RUN_ID` env var.

---

## lint Layout

`openflow lint <file>` uses an ephemeral temp dir, no persistent storage:

```
/tmp/openflow-lint-XXXX/
  go.mod                       # module openflow-lint-workflow / go 1.25
                               #   replace github.com/xhd2015/openflow/sdk => ./.openflow-sdk
  <file>.openflow.go           # copied from original location
  .openflow-sdk/               # extracted mock SDK (stub implementations)
    go.mod                     # module github.com/xhd2015/openflow/sdk
    shell.go
    agent.go
    helpers.go
    step.go
    events.go
```

The temp dir is discarded after `go build`, `go vet`, and `go run` complete.

## metadata.json

Written by the Go runner on completion.

```json
{
  "id": "20260606-abbfdab9",
  "file": "/abs/path/to/workflow.openflow.go",
  "status": "completed|failed",
  "exit_code": 0,
  "duration_ms": 12345,
  "error": "optional error message"
}
```

## events.jsonl

Appended by the SDK (`sdk/events.go`) during workflow execution. One JSON line per event.

### Event Schema

```json
{
  "type": "step|agent|shell",
  "timestamp": "2026-06-06T10:00:00.000Z",

  "step": "label",
  "status": "started|completed|failed",

  "agent": "agent-name",
  "prompt": "...",
  "result": "...",
  "duration_ms": 1234,

  "shell_name": "test",
  "cmd": "go test ./...",
  "pwd": "/abs/working/dir",
  "stdout": "...",
  "stderr": "...",
  "exit_code": 0,

  "error": "optional error message"
}
```

### Event types

| `type`  | Mandatory fields                                    | Emitted by    |
|---------|-----------------------------------------------------|---------------|
| `step`  | `step`, `status`, `timestamp`                       | `Step()`      |
| `agent` | `agent`, `prompt`, `status`, `timestamp`            | `Agent.Run()` |
| `shell` | `shell_name`, `cmd`, `pwd`, `exit_code`, `stdout`, `stderr`, `timestamp` | `Shell()` |

### Example file

```jsonl
{"type":"step","step":"GREET","status":"started","timestamp":"2026-06-06T10:00:00.000Z"}
{"type":"agent","agent":"you-are-a-helpful-assi-a1b2c3d4","status":"started","prompt":"Say hello","timestamp":"2026-06-06T10:00:00.001Z"}
{"type":"agent","agent":"you-are-a-helpful-assi-a1b2c3d4","status":"completed","result":"hello from openflow","duration_ms":2300,"timestamp":"2026-06-06T10:00:02.301Z"}
{"type":"shell","shell_name":"verify","cmd":"echo done","pwd":"/home/user/project","exit_code":0,"stdout":"done\n","stderr":"","duration_ms":5,"timestamp":"2026-06-06T10:00:02.306Z"}
{"type":"step","step":"GREET","status":"completed","timestamp":"2026-06-06T10:00:02.306Z"}
```

## agents/<agent-name>/events.jsonl

Per-agent raw trace. Written by `openflow exec --trace-dir <path>` via agent-pro's `RawLog` writer.
Contains the **unmodified** event stream from the underlying agent runner (opencode, codex, cursor).
No SDK translation or synthesis — these are the actual JSON events produced by the agent.

### Example (opencode)

```jsonl
{"type":"text","part":{"text":"hello from openflow"},"session_id":"abc123"}
{"type":"tool_use","part":{"tool":"read","path":"merge.go"},"session_id":"abc123"}
{"type":"tool_use","part":{"tool":"write","path":"merge.go"},"session_id":"abc123"}
{"type":"text","part":{"text":"Fixed the recursive merge."},"session_id":"abc123"}
```

---

## agents/<agent-name>/messages.jsonl

SDK-level message timeline. Written by `Agent.Run()`.

```json
{"type":"prompt","content":"Fix the bug in merge.go","timestamp":"2026-06-06T10:00:00.000Z"}
{"type":"feedback","content":"[shell test] go test ./... (exit 1)","timestamp":"2026-06-06T10:00:10.000Z"}
{"type":"output","content":"Fixed the recursive merge in MergeJSON.","timestamp":"2026-06-06T10:00:15.000Z"}
```

| `type`     | When                           | `content`                            |
|------------|--------------------------------|--------------------------------------|
| `prompt`   | first run (before execution)   | the task string                      |
| `feedback` | each resume (before execution) | `Feedback.String()` for each item    |
| `output`   | after agent returns            | agent response, capped at 1024 chars |

## agents/<agent-name>/shell_suggestions/

When `Shell()` fails and feedback is sent to an agent, the `<bash>` XML includes a `suggestion:` line with an absolute path to this directory. The agent can write a corrected command to `<name>.sh`.

After `Agent.Run()` returns, the SDK scans this directory:
- Reads `<name>.sh` files, stores the command in `AgentOutput.ShellSuggestions`
- Atomically renames each to `<name>_YYYYMMDD_HHMMSS.sh` (archived to avoid re-reading)

```
shell_suggestions/
  test.sh                    # agent wrote "go test -v ./..."
  test_20260606_143025.sh    # SDK renamed after reading
```

## Agent Name

If `NewAgent(AgentOpts{Name: "coder", SystemPrompt: "..."})` is used and `Name` is non-empty, the directory is `agents/coder/`.

If `Name` is omitted, it is auto-derived from the `systemPrompt`:

```
slug(first-4-words-of-system-prompt) + "-" + md5(systemPrompt)[:8]
```

Example: `SystemPrompt: "You are a Go programmer. Write clean code."` → `agents/you-are-a-go-programmer-a1b2c3d4/`

## Stdout Logging (Real-Time)

Critical events are printed to stderr in real-time with `[openflow]` prefix:

```
[openflow] step: GREET
[openflow] agent: coder run "Say hello"
[openflow] agent: coder done (2.3s)
[openflow] shell: [verify] echo done -> exit 0 (5ms)
[openflow] shell: [test] go test ./... FAILED: exit 1
[openflow] agent: coder feedback: "[shell test] go test ./... (exit 1)"
[openflow] agent: coder suggestion: test => go test -v ./...
[openflow] step: GREET done
```

- Step events: `[openflow] step: <label>` / `[openflow] step: <label> done` / `[openflow] step: <label> failed`
- Agent first run: `[openflow] agent: <name> run "<task>"`
- Agent resume: `[openflow] agent: <name> feedback: "<Feedback.String()>"`
- Agent completion: `[openflow] agent: <name> done (Xs)`
- Agent failure: `[openflow] agent: <name> failed (Xms): <stderr>`
- Agent suggestion: `[openflow] agent: <name> suggestion: <shellName> => <cmd>`
- Shell success: `[openflow] shell: [<name>] <cmd> -> exit 0 (Xms)`
- Shell failure: `[openflow] shell: [<name>] <cmd> FAILED: <stderr>`
- Console: workflow `Print()` outputs pass through to stdout naturally

## SDK Package (`sdk/`)

The SDK package provides Go primitives for workflow files:

```go
import . "github.com/xhd2015/openflow/sdk"
```

Key exports:

| Export             | Description                                           |
|--------------------|-------------------------------------------------------|
| `Feedback`         | interface `{ String(); ToAgent(name string) string }` |
| `Shell(cmd, opts)` | run shell command, returns `ShellResult`              |
| `ShellResult`      | `{ Name, Cmd, Pwd, Stdout, Stderr, ExitCode, Feedback }` |
| `ShellFeedback`    | implements `Feedback`; `ToAgent()` produces `<bash>` XML |
| `NewAgent(opts)`   | create agent, returns `*Agent`                        |
| `Agent.Run()`      | run agent, returns `(string, *AgentOutput, error)`    |
| `AgentOutput`      | `{ ShellSuggestions map[string]string }`              |
| `Step(label, fn)`  | named checkpoint for tracing                          |
| `Print(msg)`       | prints a line to stdout                               |
| `S(v any)`         | converts any value to string                          |

All writes to `events.jsonl` and `messages.jsonl` are best-effort — errors are silently ignored (file permissions, disk full, etc.).
